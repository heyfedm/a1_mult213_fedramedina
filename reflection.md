# Recipe Finder - Reflection 🥗
## Highlight any challenges you faced and how you overcame them.
- The biggest challenge was to understand how the API works and which property I have to use to get the information that I need.
- Organizing the CSS: despite having knowledge of it, it was a little bit tricky because this time it was from an API, so I had to add classes to the JS. Also, in the single recipe part, I have problems organizing the information since it overlapped, so that's why I had to use !important.
- Another challenge was that this API has a good variety, but it’s not enough because you must search for very common ingredients to get a recipe; otherwise, you are not going to get anything. So, it was important to create an error message so the user could try again.

## Mention any new concepts or techniques you learned during development.
- To understand the concepts a little bit better, I tried using different techniques of modern JS like .then() and. catch(), and also sync/await.
- Since some of the recipes had numbered properties without text, I learned how to delete those so they don’t appear on the website.
- I learned about the : has in CSS so I can make it work to adapt the content to the DOM because was the only way that I could organize my content, so I have to do research to solve that problem since in some parts my CSS it wasn’t applying to my website.

## Suggest improvements you would make if given more time.
- I would like to make it look more professional instead of playful, also separating the content on different pages.
- I would like to use more endpoints, so it has more filters, like searching by the name of the dish, the country or the category. Also, I would like to add a function so it can search just by pressing “Return” on the keyboard instead of clicking the button.
-I would like to add an animation, like a waiting indicator for the results or something similar on the search page.
